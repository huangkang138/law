# AI_WORKFLOW

日常不需要写完整 Prompt，也不需要记 Mode，直接说目标即可：

- “把这个功能做一下。”
- “这里报错了，修一下。”
- “这个页面帮我调整一下。”
- “先分析这个架构，不要改代码。”
- “检查一下刚才的实现。”
- “用验收导读讲清最终效果和怎么人工验收。”
- “带我看一下这次核心代码。”
- “这个结果我不满意，主要是 XXX。”

Agent 会先自行检查项目、必要时只问少量关键问题、自动整理 CURRENT_TASK 并自动路由。显式说“进入 FEATURE 模式”等只是高级强制指定，不是必需流程；你不必手填目标、背景、范围或验收模板。

| 文件 | 职责 |
| --- | --- |
| `WORKFLOW.md` | 工作流、自动路由、验收与返工。 |
| `LAW-DEV.md` | 日常开发：定位、最小实现、测试和 Diff 验收闭环。 |
| `LAW-REVIEW.md` | 阶段验收：默认只读，运行测试并报告 P0/P1/P2。 |
| `CODE_RULES.md` | 安全修改代码的硬约束。 |
| `MODES.md` | 七种模式的具体执行方式，包含一次讲完整的验收导读。 |
| `CURRENT_TASK.md` | 唯一当前工作。 |
| `NEXT_STEP.md` | 后续候选任务。 |
| `DECISIONS.md` | 长期决策。 |
| `DEVELOPER_MEMORY.md` | 开发者重新定位索引。 |

`newModify/` 是当前事实与历史，`raw/` 是长期规划，均不属于工作流规则正文。
