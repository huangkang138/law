# 数字人智能助手实现方案

更新时间：2026-07-11

## 一、需求概述

在法务平台中加入一个"数字人智能助手"（暂定名"法小助"），核心定位：

- **面向人群**：老人、小孩、不善打字的用户
- **全局存在**：悬浮在页面右下角，不属于某个具体功能页面
- **智能路由**：根据用户自然语言识别意图，引导跳转到对应功能（合同审查、纠纷中心等）
- **简单问答**：简单法律问题可以直接回答，复杂问题引导去专业模块
- **互动形象**：根据对话状态切换表情动画（idle、thinking、talking、serious 等）
- **对话持久化**：刷新后对话历史还在

## 二、与现有项目的关系

### 现有 Agent 系统对比

| | 现有 LegalAgentService | 现有 agent.py | 数字人助手（新增） |
|---|---|---|---|
| 定位 | 专业法律咨询 | 多角色智能体管理 | 全局导航+简单问答 |
| 提示词 | 法律专家 | 各角色专家 | 亲切的引导助手 |
| 多轮对话 | 有（10条历史） | 无 | 有（6条历史） |
| 输出 | 纯文本回答 | 纯文本回答 | 结构化JSON（reply+intent+emotion） |
| 持久化 | 数据库 | 仅记录使用 | 数据库 |

### LLM 调用方式

项目使用 DeepSeek 云端 API（非本地模型），通过 `LLMFactory.create_llm()` 创建实例，httpx 流式调用。数字人复用同一套调用逻辑，只是提示词不同。

## 三、整体架构

```
用户点击数字人 → 输入问题（文字）
    ↓
前端调用 POST /api/digital-human/chat
    ↓
后端 DigitalHumanService
  - 拼接消息：system_prompt + 历史对话(6条) + 用户输入
  - 流式调用 DeepSeek API
  - 解析返回的 JSON（reply + intent + emotion）
  - 存入数据库
    ↓
前端收到响应
  - 切换数字人表情状态
  - 显示回复文字
  - 如果有 intent 对应的功能，显示跳转按钮
  - 用户点击按钮 → router.push 跳转
```

### 4.3 API 接口设计

#### POST /api/digital-human/chat — 发送消息

请求：
```json
{
  "question": "我想看看合同有没有问题",
  "session_id": "dh_abc123"
}
```

响应：
```json
{
  "success": true,
  "reply": "你想检查合同有没有坑对吧？我们有合同审查功能，上传合同就能帮你找风险。要去看看吗？",
  "intent": "contract_review",
  "emotion": "talk_normal",
  "confidence": 0.92,
  "route": "/contract",
  "route_label": "合同审查",
  "session_id": "dh_abc123"
}
```

#### POST /api/digital-human/reset — 重置会话

请求：`{ "session_id": "dh_abc123" }`
响应：`{ "success": true, "message": "会话已重置" }`

#### GET /api/digital-human/sessions — 获取会话列表

响应：
```json
{
  "success": true,
  "sessions": [
    {
      "id": "dh_abc123",
      "title": "我想看看合同有没有问题...",
      "last_message": "你想检查合同有没有坑对吧？",
      "message_count": 4,
      "created_at": "2026-07-11T10:00:00",
      "updated_at": "2026-07-11T10:05:00"
    }
  ]
}
```

#### GET /api/digital-human/sessions/{id}/messages — 获取会话消息

响应：
```json
{
  "success": true,
  "messages": [
    { "id": "xxx", "role": "user", "content": "...", "created_at": "..." },
    { "id": "yyy", "role": "assistant", "content": "...", "intent": "contract_review", "emotion": "talk_normal", "created_at": "..." }
  ]
}
```

#### DELETE /api/digital-human/sessions/{id} — 删除会话

响应：`{ "success": true, "message": "会话删除成功" }`

### 4.5 DigitalHumanService 核心逻辑

1. **初始化**：创建 LLM 实例（复用 LLMFactory），初始化会话字典
2. **system_prompt**：定义"法小助"角色，要求 LLM 严格返回 JSON 格式
3. **_build_messages**：拼接 system_prompt + 最近6条历史 + 当前输入
4. **_invoke_llm_streaming**：httpx 流式调用 DeepSeek（直接复制 legal_agent.py 的逻辑）
5. **_parse_llm_response**：解析 JSON，处理 markdown 代码块包裹、格式错误等情况，兜底返回默认值
6. **chat**：组装完整流程，查 INTENT_ROUTE_MAP 获取路由信息，保存到数据库
7. **全局单例**：`get_digital_human_service()` 函数

### 4.6 提示词设计（system_prompt 核心思路）

```
角色：法小助，面向老人和小孩的法律服务导航助手
性格：亲切通俗、有耐心、不用复杂术语
职责：
  - 识别用户意图，引导去对应功能
  - 简单法律问题直接简短回答
  - 复杂问题引导去专业模块
回复格式：严格 JSON
  {"reply": "...", "intent": "...", "emotion": "...", "confidence": 0.8}
```

### 4.7 新增数据库表

```
digital_human_sessions 表：
  - id (String, 主键, 前缀 dh_)
  - user_id (String, 默认 anonymous)
  - title (String, 取用户首条消息前30字)
  - is_active (Boolean, 默认 True)
  - created_at (DateTime)
  - updated_at (DateTime)

digital_human_messages 表：
  - id (String, 主键)
  - session_id (String, 外键 → digital_human_sessions.id)
  - role (String, user/assistant)
  - content (Text, 消息内容)
  - intent (String, 可为空, 仅 assistant 消息有)
  - emotion (String, 可为空, 仅 assistant 消息有)
  - created_at (DateTime)
```

### 5.4 数字人状态机

```
页面加载 → idle（缓慢呼吸动画）
用户点击头像 → welcome（打招呼）
用户发送消息 → thinking（等待回复）
收到回复 → talk_normal / serious / success（根据 emotion 字段）
引导跳转 → handoff（挥手送别）
出错 → error
空闲3秒 → 回到 idle
```

### 5.5 交互流程

1. 页面右下角悬浮一个数字人小头像（idle 状态，有缓慢 scale 呼吸动画）
2. 点击头像 → 展开 384px 宽的对话面板
3. 面板布局（从上到下）：
   - 顶栏：标题"法小助" + 关闭按钮
   - 数字人大图：当前情绪状态对应的图片
   - 消息列表：对话气泡（用户靠右，助手靠左）
   - 输入框 + 发送按钮
4. 用户输入并发送 → 切换为 thinking → 调 API → 收到响应后切换 emotion
5. 如果响应中有 route（不为 null），在助手消息下方显示"去 XXX 看看"按钮
6. 点击跳转按钮 → 切换 handoff → `router.push(route)` → 延迟后收起面板

## 六、数据流全链路

```
1. 用户点击右下角头像
   → store.open()
   → emotion = 'welcome'
   → 显示欢迎语"你好呀！我是法小助，有什么能帮你的吗？"

2. 用户输入"我想看看合同有没有问题"并发送
   → store.addMessage({role:'user', content:'...'})
   → store.isLoading = true
   → emotion = 'thinking'（显示 thinking.png）

3. 前端调用 POST /api/digital-human/chat
   → 后端 DigitalHumanService.chat()
   → 拼接消息列表
   → httpx 流式调用 DeepSeek
   → 解析返回的 JSON
   → 存数据库
   → 返回结构化响应

4. 前端收到响应
   → store.isLoading = false
   → emotion = response.emotion（如 'handoff'）
   → store.addMessage({role:'assistant', content: reply, route, routeLabel})
   → 消息下方渲染跳转按钮

5. 用户点击"去合同审查看看"按钮
   → emotion = 'handoff'
   → router.push('/contract')
   → 延迟 500ms → store.close()
```

## 八、关键注意事项

1. **JSON 解析健壮性**：DeepSeek 偶尔会在 JSON 前后加 markdown 代码块标记（```json...```），后端需要 strip 处理，解析失败时兜底返回默认值
2. **图片路径**：Next.js 静态资源必须在 `public/` 下，所以状态图需要复制过去
3. **z-index**：数字人悬浮组件用 `z-[9999]`，确保在导航栏和弹窗之上
4. **懒加载**：组件用 React.lazy + Suspense，不影响首屏加载速度
5. **图片切换动画**：CSS opacity transition 300ms，避免生硬跳变
6. **会话 ID 策略**：数字人会话 ID 用 `dh_` 前缀区分，与普法问答的会话互不干扰
7. **confidence 阈值**：LLM 对意图判断的 confidence 低于 0.6 时，不做跳转引导
