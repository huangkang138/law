# 链路追踪

## 【Trace 最小全链路追踪】（`IMPLEMENTING`，2026-08-15）

### 一级调用链

[tracing.py](../../flask_app/services/conversation/tracing.py) `trace(event, trace_id, **fields)`（JSONL 写 logs/trace.jsonl + 镜像 app.log）← [digital_human_service.py](../../flask_app/services/digital_human_service.py) `request_start/request_error/request_cancelled` ← [orchestrator.py](../../flask_app/services/conversation/orchestrator.py) `route_decision/action_executed/request_completed` ← [actions.py](../../flask_app/services/conversation/actions.py) `matter_created/run_started` + `link_run(run_id, trace_id)`

### 一句话目的

正常运行时按 trace_id（=request_id）即可串起一次会话的完整链路：请求开始 → 路由决策 → 动作执行（建案/启动 Run，run_id↔trace_id 关联）→ 完成/取消/失败。不依赖调试模式，不碰 Agent 业务逻辑；步骤级明细仍以 DB AgentRun.steps 为准，Trace 负责**关联与可查询**。

### 调用链

```text
每次会话请求（trace_id = request_id，dhr_ 开头）：
前端 → /chat/stream → DigitalHumanService.chat_stream
  ├─ trace request_start {session_id, voice, question_preview(≤30字)}
  ├─ ConversationOrchestrator.chat
  │    ├─ begin_request 命中缓存 → trace request_replayed
  │    ├─ trace route_decision {route, confidence, reason_code, side_effect_authorized}
  │    ├─ actions.execute（携带 request_id）
  │    │    ├─ 建案 → trace matter_created {matter_id}
  │    │    └─ 启动 Run → link_run(run_id, trace_id) + trace run_started
  │    │                 {run_id, matter_id, task_type, status}
  │    ├─ trace action_executed {action_type, status, matter_id, run_id}
  │    └─ trace request_completed {action_type}
  │    异常分支：取消 → trace request_cancelled；其他 → trace request_failed {error}
  └─ SSE 异常 → trace request_error {code}

每个事件两处落点：
- logs/trace.jsonl（结构化 JSONL，按 trace_id 可 grep/筛选）
- app.log（[trace] 前缀镜像行，普通日志同样可见）
trace() 内部 try/except：写入失败绝不拖垮聊天主链路。
```

### 关键状态

| 状态 | 谁写 | 谁读 |
| --- | --- | --- |
| logs/trace.jsonl（每行 {ts, trace_id, event, ...}） | tracing.trace()（线程锁追加） | 人工/脚本按 trace_id 回溯 |
| run_id ↔ trace_id 映射（进程内存 dict） | link_run / unlink_run | trace_for_run（Agent 步骤回溯） |
| 事件字段（route/matter_id/run_id/task_type） | 编排器与动作挂点 | 链路报告/答辩 |

### 判断点（已查过）

- **trace_id 复用 request_id**：SSE 每个事件已带 request_id，前端可随时对上后端链路；不新增前端契约。
- **隐私边界**：question 只留 30 字预览；完整问题仍只在 DB（本地开发项目惯例）。
- **容错**：trace 写入异常全部吞掉（open 失败/磁盘故障都不影响业务，有单测覆盖）。
- **不反向依赖**：legal_agent_system（Runtime）不 import 会话层；步骤级事件不侵入 Runtime，靠 run_id 关联 DB 中已有的 AgentRun.steps。
- **动作签名兼容**：`ConversationActions.execute` 新增可选 `request_id` 参数（默认 None），3.7F 取消测试的 blocking_execute（**kwargs）兼容。
- **Action 字段名**：ConversationAction 的字段是 `action`（不是 type），to_dict 才映射为 "type"；挂点里用 `action.action`。
