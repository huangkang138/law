# 数字人语音

---

## 【3.7G 基础语音闭环】（已验收 `COMPLETED`，2026-08-15）

### 一级调用链

[ConversationComposer.tsx](../../frontend/src/components/DigitalHuman/ConversationComposer.tsx) 麦克风按钮 → [sttController.ts](../../frontend/src/lib/voice/sttController.ts) `start()`（浏览器 STT）→ 输入框确认 → [digitalHumanStore.ts](../../frontend/src/store/digitalHumanStore.ts) `sendMessage()`；回复完成 → 播报开关/气泡按钮 → `speakMessage()` → [ttsController.ts](../../frontend/src/lib/voice/ttsController.ts) `speak()`（speechSynthesis）

### 一句话目的

第一版基础语音闭环：语音只作为同一 Conversation Orchestrator 的输入输出方式。中文语音转文字进入同一 Session（后端无感知）；回复可朗读、可停止；不支持语音的浏览器文字聊天不受影响。

### 调用链

```text
【语音输入】
点麦克风（ConversationComposer，主聊天/工作台侧边/Float 三处共用）
→ stopSpeaking()（说话打断旧朗读）
→ SttController（webkitSpeechRecognition：continuous + interimResults + zh-CN）
   ├─ final 按结果下标去重（停止时 Chrome 会重放已确认结果，防"我要仲裁我要仲裁"）
   ├─ interim 始终上报（空值清空预览，停止合并时不重复）
   └─ onend 仍在录音时自动重启（Chrome 连续识别约 60s 自动结束）
→ 转写文本留在 textarea（不自动发送，须用户确认）
→ sendMessage → 同一 Session / 同一 Orchestrator

【语音输出】
发送前：ttsController.cancel()（新输入打断旧朗读）
回复完成落库后：
├─ 播报开关 voiceEnabled 开 → 自动朗读新回复
└─ assistant 气泡"朗读"按钮 → speakMessage（单条回放/停止）
→ ttsController（speechSynthesis：中文 voice 优先、filterSpeakableText 清洗
   Markdown/emoji、新朗读先 cancel）
→ 朗读期间 Avatar 显示 talk_normal 状态图
```

### 关键状态

| 状态 | 谁写 | 谁读 |
| --- | --- | --- |
| store.voiceEnabled（partialize 持久化）/ voiceSpeaking / speakingMessageId | toggleVoice / speakMessage / stopSpeaking | Composer 开关、气泡按钮、Avatar |
| SttController 实例 + 文本 base/interim ref（组件私有） | ConversationComposer | textarea 预览与确认发送 |
| sttError（权限/网络降级提示） | Composer onError | 轻量提示，不进消息列表 |

### 判断点（已查过）

- **识别去重**：`lastFinalIndex` 游标跳过已上报的最终结果；开始识别与 60s 自动重启（新识别会话下标归零）时复位。
- **权限/网络降级**：not-allowed → "未获得麦克风权限"；network → "语音识别暂不可用"；no-speech 静默继续监听；均不影响文字输入。
- **打断语义**：新输入、停止按钮、切会话/新对话/重置/删会话/关面板全部 cancel 旧朗读。
- **水合守卫**：语音能力在 useVoiceReady（浏览器环境就绪）后才判定，SSR 首帧与浏览器渲染一致；不支持语音的浏览器按钮不渲染。
- **转写须确认**：语音文本只进输入框，用户点发送才发出（法律场景不让语音自动发送）。

## 【Phase 1 句级神经 TTS】（`READY_FOR_ACCEPTANCE`，2026-08-15）

### 一级调用链

[digital_human_service.py](../../flask_app/services/digital_human_service.py) `_stream_voice_presentation` → [voice_orchestrator.py](../../flask_app/services/voice/voice_orchestrator.py) `push_text()`（句切分 + 归一化 + 合成）→ [qwen_provider.py](../../flask_app/services/voice/provider/qwen_provider.py) `synthesize()`（Qwen TTS）→ SSE `voice` 事件 → [digitalHumanApi.ts](../../frontend/src/services/digitalHumanApi.ts) 解析 → [streamingAudioPlayer.ts](../../frontend/src/lib/voice/streamingAudioPlayer.ts) `enqueue()`/`playNext()` 连续播放；停止按钮 → `cancelRequest()` → `voicePlayer.clear()` 立即打断

### 一句话目的

比赛展示可用的语音效果：回复按完整句合成为高质量神经语音，逐句连续播放、不重叠不乱序；支持立即打断与 requestId 隔离；语音失败只降级（浏览器语音/纯文字），不拖垮聊天与 Agent。3.7G 的浏览器 TTS 保留为明确标注的 FALLBACK_TTS。

### 调用链

```text
【主链路】
前端发送（voice=voiceEnabled，发送时开关值）→ POST /chat/stream
→ orchestrator.chat 完成后，_stream_voice_presentation 逐块（12 字符/块）
   喂给 VoiceOrchestrator.push_text(request_id, chunk)
→ SentenceSegmenter：。！？；成句即产出；短碎片缓冲（防"根据""你的"级 TTS）；
   80 字无标点兜底截断
→ SpeechTextNormalizer：展示文本 → 朗读文本（去 Markdown 符号/列表符、
   URL→"链接"、括号去符号留内容、12,500→12500、30%→百分之30、emoji 清除；
   法条编号/书名号/日期保持原文 —— 只变形式，不变法律含义）
→ QwenDashScopeTtsProvider（dashscope SDK SpeechSynthesizer，WebSocket 协议；
   qwen-audio-3.0-tts-flash + longanhuan_v3.6；mp3 22050Hz）
→ VoiceChunk{seq, request_id, text, tts_mode, audio_b64}
→ SSE voice 事件（与 delta 交错；seq 递增；tts_mode 明确 primary/fallback）
→ 前端解析 → data:audio/mp3;base64 → store.onVoice（双重守卫：
   发送时 voiceRequested + 当前 voiceEnabled）
→ StreamingAudioPlayer.enqueue（requestId 不匹配直接丢弃）
→ playNext 一次一条：primary 走 <audio>；fallback 走 speechSynthesis
→ 播放回调 → store.voiceSpeaking / speakingMessageId / voiceMode
→ Avatar voiceSpeaking → talk_normal 状态图

【打断 / 取消】
停止按钮 → store.cancelRequest
→ 后端：set_cancelled + voice_orchestrator.cancel(request_id)
         （丢句缓冲 + provider.cancel；多句合成之间检查取消；迟到结果丢弃）
→ 呈现循环 is_cancelled → 不再下发 delta/voice → SSE error(CANCELLED)
→ 前端：ttsController.cancel + voicePlayer.clear（停在播音频 + 清队列）
→ 新消息：voicePlayer.setRequest(新 requestId) → 旧请求迟到 voice 事件
   双重被拒（onVoice 操作序列 + 播放器 requestId 隔离）

【降级 / 开关】
Provider 未配置/合成失败/空音频 → tts_mode="fallback"，该请求其余句子锁存
fallback（不反复调供应商/刷日志）；关闭语音 = stopSpeaking + player.clear，
只停语音不影响文字与 Agent；重新开启只朗读后续新回复（发送时 voiceRequested
守卫，不补读历史）。
```

### 关键状态

| 状态 | 谁写 | 谁读 |
| --- | --- | --- |
| 后端句缓冲 / seq / cancelled / provider_failed（按 request_id，进程内存） | VoiceOrchestrator push_text/finish/cancel | SSE voice 事件生成 |
| VoiceChunk.audio_b64 / tts_mode | orchestrator._synthesize（provider 结果） | SSE → 前端 data URL / 播放器 |
| 播放器队列 / 当前段 / requestId 作用域 / IDLE-BUFFERING-PLAYING-PAUSED-STOPPED-ERROR | StreamingAudioPlayer（模块级单例） | store 回调、组件状态 |
| store.voiceMode（primary/fallback 明确区分，不静默混用） | 播放器 onSpeechStart | 语音模式可观测 |

### 判断点（已查过）

- **句级流式边界**：3.7F 是"已验证回复的呈现流"，LLM 全文完成后才开始句级合成；首句播放与后续句合成并行。token 级真增量需动 Orchestrator 主链路，未做（用户边界）。
- **qwen-audio-3.0-tts-flash 协议**：不走 multimodal-generation HTTP（实测 403/400），必须用 dashscope SDK WebSocket；语速参数名是 speech_rate；format 需映射 AudioFormat 枚举；默认全局 WS 地址可用，北京区域 MaaS 不通。
- **密钥边界**：DASHSCOPE_API_KEY 等只从环境变量（flask_app/.env）读取，禁止硬编码进代码或前端；config.py 曾误贴密钥已恢复。
- **迟到音频隔离**：requestId 双重守卫（store onVoice 操作序列 + 播放器 setRequest），请求 A 的迟到 voice 事件不可能进入 B 的队列。
- **异常不卡队列**：单条音频 error → 跳过播下一条；Provider 失败按请求锁存 fallback；合成失败不影响文字/Agent/工作台。
- **播放顺序**：一次只播一条，seq 递增 + 单队列 FIFO；不允许重叠与乱序。
- **暂停边界**：fallback（speechSynthesis）不支持暂停恢复，暂停即取消当前段、恢复重读；primary 走 audioEl.pause/resume。
