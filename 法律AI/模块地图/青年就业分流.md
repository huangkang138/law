# 青年就业分流

## 一级调用链

用户提问 → Router.authorizes_labor_triage → Actions._create_labor_case → create_matter → select_matter → update_labor_case_triage → 追问 / 校验 task_type → start_task → Run

## 一句话目的

劳动用工问题 → 结构化分流（场景/学生身份/诉求类型）→ 劳动关系初筛 → 缺失事实单问题追问 → 事实完整后启动对应任务类型（咨询/关系评估/案件分析）。候选事实不自动成为确认事实；高风险不自动推进。

## 调用链

```text
聊天侧（chat 动作）：
用户提问含劳动关键词 + 明确建案意图
→ ConversationRouter.authorizes_labor_triage（只依据当前输入正则，LLM 不参与授权）
→ actions._create_labor_case
    ├─ 幂等：planned matter_id → facade.get_matter → 同 session list_matters → create_matter
    ├─ workspace.select_matter（版本 CAS；冲突时保留用户新选择，不抢回指针）
    ├─ _infer_labor_facts（正则提取 scenario_type / student_status / claim_types / urgent_risks）
    ├─ facade.update_labor_case_triage → LaborCaseTriage 快照（facts / result / version）
    ├─ result.missing_facts 非空 → ask_one_key_question（awaiting_information，单问题追问）
    ├─ result.risk_level == high → stop_for_risk（不自动推进）
    └─ _validated_task_type（triage_type ↔ recommended_task_type 双向校验）
         → facade.start_task（labor_consultation / labor_relationship_assessment / labor_case_analysis）

工作台侧（useLaborTriage）：
isLaborQuestion → createDigitalHumanMatter（Idempotency-Key → 稳定 matter_id，直接返回权威 Workspace 快照）
→ updateLaborCaseTriage → taskTypeFor（前端同样双向校验）→ startLaborDisputeAgentRun
→ 恢复：workspace.run / laborContextBySession → getLaborCaseTriage + getDigitalHumanAgentRun
```

## 关键状态

| 状态 | 谁写 | 谁读 |
| --- | --- | --- |
| LaborCaseTriage（matter_id 主键：facts_json / result_json / version） | facade.update_labor_case_triage | get_context 投影 / 前端恢复 |
| Matter（status/session_id） | create_matter（幂等 ID） | 指针解析、删除回退 |
| ConversationWorkspaceState.active_matter_id + version | select_matter | get_context / 后台建案 CAS |
| AgentRun（task_type/status） | facade.start_task | 工作台恢复 / Presenter |
| triage result：triage_type / missing_facts / questions / risk_level / recommended_task_type / dispute_tags | 分流服务 | 动作决策 / 前端 LaborTriageCard |

## 判断点（已查过）

- **授权只来自确定性规则**：`authorizes_labor_triage` 只匹配当前输入；LLM 只能建议 labor_triage，被压回 normal_chat。
- **任务类型双向校验**：`triage_type` 与 `recommended_task_type` 必须一致才启动 Run，LLM/前端都无权直接指定。
- **候选 ≠ 确认**：triage 事实与材料提取候选都必须用户补录/采用，不自动写入正式事实。
- **高风险失败关闭**：risk_level=high → stop_for_risk，不自动推进、不包装成确定结论。
- **缺失事实只追问一个**：ask_one_key_question 取 questions[0]，不一次抛全量问题。
- **后台建案不抢指针**：expected_workspace_version 冲突时 pass，保留用户新选择。
