# 服务端取消

## 一级调用链

停止按钮 → /chat/cancel → cancel_request → 进程标志 + mark_cancelling → 分块循环发现 → close 中止模型 → mark_cancelled → SSE error(CANCELLED) → 前端提示

## 一句话目的

用户按停止后，服务端**真正中止在途 LLM 执行**并安全落库（不伪装）；同 request_id 重试可幂等恢复；动作执行中不强制中断（劳动副作用幂等保留）。

## 调用链

```text
停止按钮 → store.cancelRequest
→ 先 fire-and-forget：cancelDigitalHumanChatRequest(activeRequestId)
→ POST /api/digital-human/chat/cancel（router 校验 request_id + 身份归属）
→ DigitalHumanService.cancel_request
    ├─ set_cancelled(request_id)          # 进程级标志（请求行未建也先生效）
    ├─ 读行：不存在 404 / 非本人 403 / 终态 → {cancelled:false}
    └─ 会话锁内 mark_cancelling()         # DB 状态 cancelling（保留租约+检查点）
在途线程（与上面并发）：
→ _stream_joined 分块循环：is_cancelled(进程标志 ∨ 0.5s 节流 DB 轮询)
→ break + stream.close()                  # GeneratorExit → openai Stream → httpx 中止模型请求
→ raise ConversationCancelled             # 不继承 RuntimeError（防被 409 分支截获）
→ orchestrator.chat() except 分流：取消 → mark_cancelled（租约断言、清租约、保留 checkpoint）
→ SSE error 事件（code=CANCELLED, retryable=true）
→ 前端 catch：不追加错误气泡，提示"已停止回复"
```

## 关键状态

| 状态 | 谁写 | 谁读 |
| --- | --- | --- |
| 进程标志（threading.Event 注册表，15min TTL） | set_cancelled / DB 轮询命中 | 分块循环、_ensure_not_cancelled |
| DigitalHumanRequest.status（+cancelling/cancelled） | mark_cancelling / mark_cancelled / begin_request | 轮询、begin_request 分支 |
| lease_token / lease_expires_at | begin_request 签发 / mark_cancelled 清空 | _assert_lease（终局仲裁者） |
| checkpoint_json / action_resource_json | mark_action_*（取消时**保留**） | 重试恢复路径 |
| 前端 activeRequestId | sendMessage 设 / finally 清 | cancelRequest |

## 判断点（已查过）

- **取消先到、请求行未建**：arm 后、begin_request 前查进程标志 → 短路不落库。
- **begin_request 期间取消到达**：begin_request 后带 DB 轮询再查一次。
- **重试穿透**：cancelling + 有效租约 → 拒绝（防并发双跑）；租约过期 + 有检查点 → action_running 幂等恢复；无检查点 → processing 重跑。
- **双重终局**：mark_cancelled 的租约断言是仲裁者，先到者胜。
- **取消检查点位置**：动作快路径前 / 动作执行前 / 动作执行后 / 完成前各一处；动作执行中不检查。
- **动作阶段取消**：副作用已落库则保留（Matter/Run 幂等复用），重试恢复不重复创建。
- **completed 后取消**：no-op。
- **已知边界**：跨 worker 取消延迟 ≤1s（轮询节流）；断连（非点击停止）不触发取消。

## Phase 1 语音取消扩展（2026-08-15）

停止生成在 3.7F 基础上多一环语音（见《数字人语音》）：

- `cancel_request` 在 `set_cancelled` 后调 `voice_orchestrator.cancel(request_id)`：丢句缓冲 + 供应商取消；多句合成之间检查取消，发现即停；取消后迟到合成结果丢弃。
- 呈现循环 `_stream_voice_presentation` 每块检查 `is_cancelled` → 不再下发 delta/voice → CANCELLED 收尾。
- 前端 `cancelRequest`：`ttsController.cancel()` + `voicePlayer.clear()`（停在播音频 + 清队列）；新消息发送时 `voicePlayer.setRequest(新 requestId)`，旧请求迟到 voice 事件双重被拒（onVoice 操作序列守卫 + 播放器 requestId 隔离），绝不进入新请求队列。
