## 一级调用链

前端发送 → /chat/stream → DigitalHumanService → ConversationOrchestrator → Router → LLM → Actions → complete_request → SSE → 前端（voice=true 时 delta 与句级 voice 事件交错，见《数字人语音》）

## 一句话目的

用户自然语言 → 法小助回答：识别意图、完成路由、必要时触发受控动作（建案/分流/启动任务），并保证同一条消息重复提交不产生重复副作用。SSE 只呈现"服务端完成解析、路由、安全校验和持久化之后"的已验证回复。

## 调用链

```text
前端发送（ConversationComposer → store.sendMessage）
→ sendDigitalHumanMessageStream（digitalHumanApi，fetch + ReadableStream 读 SSE）
→ POST /api/digital-human/chat/stream（router：参数校验、身份解析）
→ DigitalHumanService.chat_stream 生成器：yield accepted → thinking
→ ConversationOrchestrator.chat（唯一编排入口）
    ├─ arm(request_id) + begin_request（请求幂等/租约，会话级 advisory lock 只包短事务）
    ├─ Router 确定性路由：
    │   高风险 → 固定安全文案（不调 LLM）
    │   劳动关键词 → labor_triage（仅当前输入满足明确建案意图才授权副作用）
    │             → labor_consultation
    │   其他 → LLM 结构化回退（封闭 schema）
    ├─ invoke_llm：LLM 流式完整消费；响应非 JSON 时追加"严格 JSON"指令重试一次
    ├─ parse_llm_response：围栏清理 → 直接解析 → 平衡提取 → 修复（裸换行/尾逗号）
    │   → 纯文本降级（模型真实回答，剔除 **）→ 固定兜底句（最后手段）
    ├─ 二次路由：LLM 只能建议，不能授权副作用；side_effect_authorized 只来自确定性规则
    ├─ actions.execute：reply_only / ask_one_key_question / start_agent /
    │                   guide_to_workspace / stop_for_risk
    └─ complete_request：assistant 消息 + Memory + response_json 落库
→ delta 分块下发（拼接 == completed.reply）→ completed（完整 result）
```

> Phase 1 扩展（2026-08-15）：请求带 `voice=true` 时，呈现层 `_stream_voice_presentation`
> 在 delta 之间按句插入 `voice` 事件（句级切分→归一化→后端 TTS→前端队列播放），
> 详见《数字人语音》模块文档。纯文本路径与事件序完全不变（voice 事件只在 voice=true 出现）。

## 判断点（已查过）

- **幂等**：同 request_id → completed 返回缓存；retryable/action_retryable 恢复；同 request_id 不同问题拒绝；同会话并发第二请求拒绝。
- **LLM 不能授权副作用**：`llm_side_effect_not_authorized` 分支把 LLM 建议的 labor_triage 压回 normal_chat。
- **用户输入不提升权限**：记忆与摘要以 user 上下文注入，不进 system。
- **兜底句不复读循环**：解析失败先降级为模型纯文本（真实回答进历史），固定兜底句只作最后手段。
- **迟到响应不覆盖**：conversationOperationSequence（发送/取消/切换）+ hydrationSequence（会话恢复）。
