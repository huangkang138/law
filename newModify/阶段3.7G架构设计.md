# 阶段 3.7G 架构设计：基础语音闭环

## 1. 结论

3.7G 把语音做成同一 Conversation Orchestrator 的纯前端输入输出方式，后端零改动（对现有 Agent 无影响）：

```text
语音输入 → 浏览器 STT（webkitSpeechRecognition）
  → 文本进入现有 textarea → sendMessage → 同一 Session / 同一 Orchestrator
  → SSE 流式文本（3.7F 已有）
  → 回复完成后 TTS 朗读（speechSynthesis，全局开关/气泡按钮）
  → 朗读期间 Avatar 显示 talk_normal 状态图
```

关键事实：
- `VoiceCourtroom.tsx` 已验证 Web Speech 两条链路可用（Chrome/Edge）：STT `SpeechRecognition`（zh-CN、continuous、interimResults）与 TTS `speechSynthesis`（中文 voice 选择、队列、暂停/跳过）。3.7G 只提取其经验为独立轻量控制器，不引用模拟法庭业务组件。
- 后端不新增路由、不改契约：转写文本走现有 `POST /api/digital-human/chat/stream`，朗读的是 `completed` 事件里的已校验 reply。
- 头像情绪是静态 PNG 状态图（`/digital-human/first-gen/*.png`），`talk_normal`（"正在为你解答"）已存在 —— 第一版"speaking 动画"即朗读期间切换该状态图，高精度口型明确不做。

## 2. 独立语音控制器（新增 `frontend/src/lib/voice/`）

两个轻量控制器，与业务组件解耦，均带 SSR 守卫（`typeof window === 'undefined'` 直接降级）：

### `sttController.ts`（语音转文字）

- `isSupported()`：检测 `window.SpeechRecognition || window.webkitSpeechRecognition`。
- `start({ onFinal, onInterim, onError, onEnd })`：`continuous=true`、`interimResults=true`、`lang='zh-CN'`、`maxAlternatives=1`；final 与 interim 分开回调（VoiceCourtroom 经验：final 累积进输入框、interim 只做预览，防止重复叠加）。
- Chrome 连续识别约 60s 会自动停止：`onend` 时若仍在录音则自动 `start()` 重启（VoiceCourtroom 已验证的写法），`recognition.start()` 抛错吞掉并回调 onError。
- `stop()`：置录音标志后 `recognition.stop()`；`abort()` 用于组件卸载/会话切换。
- 错误映射：`not-allowed`（麦克风权限被拒）→"未获得麦克风权限"；`no-speech`/`network` →"语音识别暂不可用"，不打断文字聊天。

### `ttsController.ts`（文字转语音）

- `isSupported()`：检测 `window.speechSynthesis`。
- `speak(text, { onStart, onEnd, onError })`：朗读前先 `cancel()`（新朗读打断旧朗读）；内容经 `filterText()` 清洗后新建 `SpeechSynthesisUtterance`。
- `filterText(text)`（从 VoiceCourtroom 移植并收敛为纯函数，便于单测）：去 `【】/[]/（）/()` 注释块、去 `**/#/•` 等 Markdown 符号、去 emoji、压缩空白。**新增**：数字人回复无"审判长："类角色前缀，保留原有 `**加粗**` 等符号的去除规则即可，不做正则过拟合。
- `cancel()`：`speechSynthesis.cancel()` 并复位状态。
- 中文 voice 选择：优先 `lang` 含 `zh` 的 voice（女声名优先：Xiaoxiao/Xiaoyi/Huihui/Xia，VoiceCourtroom 已验证名单）；无中文 voice 时用系统默认 voice 仍朗读（不阻断）；`utterance.lang='zh-CN'`、`rate=1`（不引速度 UI，第一版保持简单）。
- 状态回调驱动 UI：onStart/onEnd/onError 均上报，onError 不弹错误气泡（朗读失败静默回退文字，不打断聊天）。

## 3. Store 集成（`digitalHumanStore.ts`）

新增状态：

- `voiceEnabled: boolean` —— 全局"自动朗读新回复"开关，**默认关闭**（不打扰纯文字用户；语音用户开一次即持久化）。加入 `partialize`。
- `voiceSpeaking: boolean`、`speakingMessageId: string | null` —— 当前朗读状态与对应气泡（驱动气泡按钮与 Avatar）。

新增动作：

- `toggleVoice()`：切换开关；关闭时立即 `tts.cancel()`。
- `speakMessage(messageId, content)`：气泡"朗读"按钮回放；`speakingMessageId` 为同一条时改为停止（按钮复用为停止态）。
- `stopSpeaking()`：`tts.cancel()` + 复位。

集成点（在既有动作内最小插入，不新开并发路径）：

- `sendMessage` 开头：`tts.cancel()`（**新输入打断旧朗读**）。
- `sendMessage` 成功落库后：`voiceEnabled` 为真 → `tts.speak(response.reply)` 并记录 `speakingMessageId`；异常/CANCELLED 路径不朗读。
- `cancelRequest`（3.7F 停止按钮）：`tts.cancel()` —— 停止 = 取消 LLM + 取消朗读。
- `loadSession`/`startNewConversation`/`reset`/`deleteSession`/`close`：`tts.cancel()`。
- TTS onStart/onEnd/onError 回调同步 `voiceSpeaking`/`speakingMessageId`（操作序列守卫同既有模式：仅当序列号未变时更新）。

Avatar speaking 动画：Chat 与 Companion 渲染处 `emotion={voiceSpeaking ? 'talk_normal' : emotion}`，不新增情绪枚举、不动 `setEmotion` 语义。

## 4. UI 接入（复用现有入口）

### `ConversationComposer.tsx`（主聊天 + 工作台侧边 + Float 三处共用，compact 变体同样生效）

- **麦克风按钮**（`Mic`/`MicOff`，lucide 已有）：`sttController.isSupported()` 为假时不渲染（验收：不影响文字聊天）；点击开始识别 → interim 实时写入 textarea 预览、final 累积；再次点击停止，转写文本留在 textarea 由用户确认/编辑后发送（法律场景不让语音自动发送）；识别中点击发送 → 先停识别再发送；识别开始即 `tts.cancel()`（说话打断朗读）。`not-allowed`/`network` 错误显示轻量提示文字，不进消息列表。
- **播报开关按钮**（`Volume2`/`VolumeX`）：切换 `voiceEnabled`，title 说明"自动朗读新回复"。
- 按钮样式：在 `DigitalHumanFloat.tsx` styled-jsx 中**追加**新 class（`.dh-voice-button` 等），不改动既有 class。

### 气泡朗读按钮（`DigitalHumanChat.tsx` + `DigitalHumanCompanion.tsx`）

- assistant 消息气泡旁追加"朗读"小按钮：点击 `speakMessage(message.id, message.content)`；`speakingMessageId === message.id` 时显示停止态。用户消息与流式临时消息不显示。
- 朗读内容即该气泡的已校验 reply（经 `filterText` 清洗），与自动朗读共用同一控制器。

## 5. 降级与边界

- `SpeechRecognition` 不支持（Firefox/Safari）：麦克风按钮不渲染，文字聊天完全不受影响。
- `speechSynthesis` 不支持：播报开关与气泡朗读按钮不渲染。
- 中文 voice 缺失：用系统默认 voice，仍朗读。
- 麦克风权限拒绝 / 识别网络失败：轻量提示，不影响文字输入。
- 朗读失败（utterance onError）：静默回退，不追加错误气泡。
- 不做：高精度口型、复杂音频流、专业级 Barge-in（打断=前端 cancel 旧朗读）、独立语音 Agent、为语音建第二套 Session/Memory/Router/Orchestrator、语音自动退化文字发送（转写文本始终经用户确认）。
- 已知边界：Chrome 连续识别约 60s 自动结束（onend 自动重启覆盖）；跨浏览器语音质量差异由浏览器/系统负责。

## 7. 范围边界

- 仅前端：`src/lib/voice/*`（新增）、`digitalHumanStore.ts`、`ConversationComposer.tsx`、`DigitalHumanChat.tsx`、`DigitalHumanCompanion.tsx`、`DigitalHumanFloat.tsx`（仅追加 styled-jsx class）。
- 不修改：后端路由/服务/模型、SSE 协议、数据库、迁移、Runtime Graph、劳动规则、审批流程、`digitalHumanApi.ts` 契约。
- 不新建语音 Agent、不复制 Orchestrator；语音文本与键盘文本在服务端完全不可区分（无 `voice` 标记字段）。

## 8. 验收矩阵

| # | 验收（源自总体规划 3.7G） | 对应实现 |
| --- | --- | --- |
| 1 | Chrome/Edge 中文语音能转文字并进入同一 Session | Composer 麦克风 → sttController → textarea → 既有 sendMessage（同一 sessionId） |
